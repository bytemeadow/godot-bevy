## Dependencies: Bevy 0.20 and Rust 1.97.1

Update Bevy to 0.20 and use Rust 1.97.1 or newer. Follow
[Bevy's 0.19 to 0.20 migration guide](https://bevy.org/learn/migration-guides/0-19-to-0-20/)
for changes in your systems and plugins.

The change most users will hit is the lifecycle observer syntax: `On<Add, T>`
becomes `On<Add<T>>`. The same applies to `Insert`, `Discard`, `Remove`, and
`Despawn` observers.

```rust,ignore
app.add_observer(|event: On<Add<Player>>| {
    println!("player added: {:?}", event.entity);
});
```

## Breaking: Math types moved to separate crates

`godot_bevy::bevy_math` no longer re-exports primitives, bounding volumes, rays,
or cubic splines. Use `bevy_shape` for primitives, bounding volumes, and rays;
use `bevy_curve` for cubic splines. Add the corresponding 0.20 crate to your
manifest if you depended on these paths. Vectors, quaternions, and matrices
remain in `bevy_math`.

## Behavior: Panic diagnostics and error handling

Bevy 0.20 no longer prints the system name when a system panics. Panicking
Godot accessors now report the caller's file and line, so a failed node lookup
points to your system instead of the accessor implementation. Returned packed
scene errors include the scene path or handle, entity, and operation; Bevy's
default error handler also reports the system name for these errors.

An unhandled panic tears down the hosted app. To log system errors and panics
and keep running, set a custom handler during app setup:

```rust,ignore
app.set_error_handler(bevy::ecs::error::warn);
```

A panicking system may leave state half-updated. Use a non-panicking handler
only when your application can tolerate that state.

## Behavior: High time scales are capped

Bevy 0.20 applies `Time<Virtual>::max_delta` after multiplying the raw frame
delta by the relative speed. With the default 250 ms cap, `Engine.time_scale`
above roughly 15× at 60 fps stops increasing the virtual delta. Slower frames
reach the cap at lower scales.

Raise `max_delta` if your game needs to fast-forward further:

```rust,ignore
app.world_mut()
    .resource_mut::<Time<Virtual>>()
    .set_max_delta(std::time::Duration::from_secs(1));
```

`FixedUpdate` is unaffected by this cap: godot-bevy advances `Time<Fixed>` from
Godot's physics delta. An explicit read of `Time<Virtual>` in a fixed system
still sees the capped clock.

## Behavior: Event observers see the current scene tree and time

Godot event-bridge and signal observers run after scene-tree mirroring and the
time update in `First`. They can see nodes added that frame and read the
current frame's time. Previously their order relative to those systems was
unspecified.

## Breaking: Resource accessors take shared references

`GodotResource::get` and `try_cast`, and `GodotResourceHandle::get` and `try_get`,
take `&self`. Systems that only read resources can use `Res<Assets<GodotResource>>`
and `Assets::get`. Handle-based audio playback and scene spawning no longer
emit `AssetEvent::Modified` just from reading an asset.

The returned `Gd` still refers to the shared Godot resource. Mutating it changes
that resource for other users too; a shared Rust reference does not make the
Godot object immutable.

## New: Reproducible schedule shuffling in tests

`godot-bevy-test` accepts `--schedule-seed <u64>` or `ITEST_SCHEDULE_SEED` to
shuffle test schedules. Each test derives its seed from the supplied value and
its name. Shuffled schedules run single-threaded, and repeats reuse the same
seed so failures reproduce.

```bash
itest --schedule-seed 42
```

## Dependencies: Two glam versions and Tracy clients

gdext uses glam 0.32 while Bevy uses glam 0.33, so both versions compile until
gdext updates. Bevy math no longer gets `debug-glam-assert` through feature
unification with gdext. Enable `bevy_math/debug_glam_assert` if you rely on
those debug checks.

Enabling both `bevy/trace_tracy` and godot-bevy's `trace_tracy` builds two Tracy
clients because the dependencies use different client versions. Enable only
the integration you need.
